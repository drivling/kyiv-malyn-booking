# 🔔 Нагадування Telegram на Railway (cron)

Як запустити автоматичні нагадування про поїздки, коли бекенд задеплоєний на [Railway](https://railway.com).

Railway **не має вбудованого cron**, тому використовуємо зовнішній сервіс, який щодня викликає ваш backend.

---

## Що вже є в проєкті

1. **За день до поїздки** — нагадування «завтра у вас поїздка» (щодня ввечері).
2. **В день поїздки вранці** — нагадування «сьогодні у вас поїздка» (щодня вранці).
3. **Очищення старих Viber оголошень** — деактивація оголошень, у яких дата по вже минула (наприклад, кожні 1–2 години).
4. **Завантаження з групи PoDoroguem** — автоматичний імпорт нових повідомлень з Telegram-групи (Малин-Київ, Малин-Житомир, Малин-Коростень) без ручного натискання в боті (кожні 2 години).

Усі викликаються через HTTP POST на ваш backend з адмін-заголовком.

---

## Крок 1: URL вашого backend на Railway

1. Відкрийте проект: [Railway Dashboard](https://railway.com/project/b43d0897-c2ac-4ec5-883a-1a238e87a997) (або ваш проект).
2. Виберіть сервіс **backend**.
3. **Settings** → **Networking** → **Public Networking**.
4. Скопіюйте **URL** (наприклад: `https://kyiv-malyn-booking-production.up.railway.app`).  
   Якщо домен ще не згенерований — натисніть **Generate Domain**.

Збережіть цей URL — він потрібен для cron.

---

## Крок 2: Авторизація (обов’язково)

Ендпоінти захищені адмін-токеном. У заголовок кожного запиту потрібно додати:

```
Authorization: <ADMIN_TOKEN>
```

`<ADMIN_TOKEN>` — токен, який бекенд повертає після логіну в адмінку: HMAC-SHA256 від `ADMIN_PASSWORD`
(64 hex-символи). Отримати його можна запитом:

```bash
curl -s -X POST "https://ВАШ-BACKEND-URL.railway.app/admin/login" \
  -H "Content-Type: application/json" -d '{"password":"ВАШ_ADMIN_PASSWORD"}'
# → {"token":"…","success":true}
```

або без запиту до сервера:

```bash
printf '%s' admin-session-v1 | openssl dgst -sha256 -hmac 'ВАШ_ADMIN_PASSWORD'
```

Токен не змінюється, доки не зміниться `ADMIN_PASSWORD`. Після зміни пароля оновіть заголовок у всіх
cronjob'ах і `VIBER_ADMIN_TOKEN` Viber-парсера. Це секрет — не публікуйте його.
Старий фіксований `admin-authenticated` більше не приймається.

Без цього заголовка відповідь буде `401 Unauthorized`.

---

## Крок 3: Налаштування cron (безкоштовно)

Підійде будь-який сервіс, що робить HTTP-запити за розкладом, наприклад:

- [cron-job.org](https://cron-job.org) (безкоштовно)
- [easycron.com](https://www.easycron.com)
- [Uptime Robot](https://uptimerobot.com) (моніторинг + HTTP hit за розкладом)

### Приклад: cron-job.org

1. Зареєструйтесь на [cron-job.org](https://cron-job.org).
2. **Create Cronjob**.
3. ~~Нагадування «завтра» (20:00)~~ і 4. ~~Нагадування «сьогодні» (08:00)~~ — **cron-job більше не потрібен**:
   бекенд сам шле нагадування за розкладом за київським часом (див. «Нагадування про поїздки» нижче).
   Видаліть jobs `Telegram: нагадування за день до поїздки` і `Telegram: нагадування в день поїздки`.

5. ~~Очистити старі Viber оголошення~~ — **cron-job більше не потрібен**: бекенд сам щоп'ять хвилин
   деактивує протерміновані оголошення (`VIBER_CLEANUP_INTERVAL_MIN`, `0` — вимкнено), а сайт
   (список, пошук, контакт) фільтрує за `endsAt` під час читання — оголошення зникає через
   **1 год після кінця часу відправлення** незалежно від таймера. Видаліть job
   `Viber: очистити старі оголошення` у cron-job.org.

6. ~~Архів старих Viber оголошень (раз на місяць)~~ — **cron-job більше не потрібен**: архів ідемпотентний і
   запускається таймером у процесі щодоби (`VIBER_ARCHIVE_INTERVAL_MIN`, `0` — вимкнено; перший запуск через
   10 хв після старту). Видаліть job `Viber: архів старих оголошень`.

7. ~~Завантажити нові повідомлення з групи PoDoroguem~~ — **cron-job більше не потрібен**: бекенд сам
   імпортує групи попуток з «Джури» (див. «Імпорт груп попуток» нижче). Якщо в cron-job.org лишився
   job `Telegram: fetch group messages` — вимкніть/видаліть його.

Підставте замість `ВАШ-BACKEND-URL` реальний домен backend з кроку 1.

## Перевірка вручну (curl)

Перед налаштуванням cron перевірте, що backend доступний і приймає запити (`ADMIN_TOKEN` — з кроку 2):

**Нагадування за день до поїздки:**
```bash
curl -X POST "https://ВАШ-BACKEND-URL.railway.app/telegram/send-reminders" \
  -H "Authorization: $ADMIN_TOKEN"
```

**Нагадування в день поїздки:**
```bash
curl -X POST "https://ВАШ-BACKEND-URL.railway.app/telegram/send-reminders-today" \
  -H "Authorization: $ADMIN_TOKEN"
```

**Очистити старі Viber оголошення:**
```bash
curl -X POST "https://ВАШ-BACKEND-URL.railway.app/viber-listings/cleanup-old" \
  -H "Authorization: $ADMIN_TOKEN"
```
У відповіді буде JSON, наприклад: `{"success":true,"deactivated":2,"message":"Деактивовано 2 оголошень"}`.

**Завантажити нові повідомлення з групи PoDoroguem:**
```bash
curl -X POST "https://ВАШ-BACKEND-URL.railway.app/telegram/fetch-group-messages" \
  -H "Authorization: $ADMIN_TOKEN"
```
У відповіді буде JSON, наприклад: `{"success":true,"message":"Імпортовано 3 нових з 5 повідомлень","created":3,"total":5}` або `{"success":true,"message":"Немає нових повідомлень","created":0,"total":0}`.

У відповіді на нагадування очікується JSON, наприклад:
```json
{
  "success": true,
  "message": "Нагадування відправлено: 3, помилок: 0",
  "total": 3,
  "sent": 3,
  "failed": 0
}
```

Якщо Telegram не налаштовано на backend, буде `400` з текстом про те, що бот не налаштовано.

## Що роблять endpoint’и

| Endpoint | Коли викликати (рекомендовано) | Що робить |
|----------|--------------------------------|------------|
| `POST /telegram/send-reminders` | **Не потрібен** (лише вручну; таймер у процесі) | Шукає бронювання на **завтра**, відправляє в Telegram нагадування «завтра у вас поїздка». |
| `POST /telegram/send-reminders-today` | **Не потрібен** (лише вручну; таймер у процесі) | Шукає бронювання на **сьогодні**, відправляє нагадування «сьогодні у вас поїздка». |
| `POST /viber-listings/cleanup-old` | **Не потрібен** (лише вручну; таймер у процесі, кожні 5 хв) | Деактивує Viber оголошення, у яких **дата по** (`endsAt` = дата + кінець часу) минула більш ніж на **1 год** (одним `updateMany` по індексу), і переводить протерміновані запити пасажир→водій у `expired`. |
| `POST /viber-listings/archive-old?days=90` | **Не потрібен** (лише вручну; таймер щодоби) | Копіює нові оголошення в аналітику (`ViberRideEvent`) і видаляє **неактивні** оголошення старші за N днів (мінімум 30), щоб гаряча таблиця не росла безкінечно. |
| `POST /telegram/fetch-group-messages` | **Не потрібен** (лише вручну) | Те саме, що робить внутрішній планувальник: нові повідомлення груп попуток → Viber listings. Відповідь містить `missingGroups` / `enabledGroups`. |

Нагадування отримують тільки бронювання, у яких заповнений `telegramChatId` (користувач підписаний на бота).

## Чеклист

- [ ] Backend задеплоєний на Railway, згенерований публічний URL.
- [ ] У backend змінні оточення: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID` (див. `RAILWAY_SETUP.md`).
- [ ] Перевірено вручну: `curl` на обидва endpoint’и з заголовком `Authorization: <ADMIN_TOKEN>` (крок 2).
- [ ] Зовнішніх cronjob'ів більше не потрібно: нагадування, очищення й архів оголошень та імпорт груп працюють таймерами в процесі бекенду (старі jobs у cron-job.org видаліть).
- [ ] Час виклику в налаштуваннях cron відповідає вашому часовому поясу.

Після цього нагадування про поїздки будуть відправлятися автоматично.

## Імпорт груп попуток (замість cron-job.org)

`backend/src/telegram-dzhura-source.ts`: кожні `TELEGRAM_IMPORT_INTERVAL_MIN` хв (за замовч. **10**, `0` — вимкнено)
процес бекенду читає нові повідомлення груп `PoDoroguem` (топіки 2/6/108), `poputka_zhytomyr_kyiv`,
`poputka_zhitomir`, `Korosten_Kyiv` з таблиці `DzhuraMessage` — їх уже пише слухач Джури, окремого
Telethon-spawn немає. Курсор — той самий `TelegramFetchState`, тож перехід з cron безшовний.

Вимоги: `DZHURA_ENABLED` не `0`; групи є в `/admin/dzhura` (кнопка «Оновити список»). Якщо для групи
вимкнено «Читати», планувальник вмикає її сам; повідомлення до цього моменту підтягніть backfill-ом.
Група, якої Джура не бачить, потрапляє в `missingGroups` відповіді ручного POST і в лог.

---

## Строк життя оголошень попуток

`backend/src/viber-listing-expiry.ts`: `endsAt` = доба поїздки + кінець `departureTime` **за київським
часом** (у UTC). Оголошення видно на сайті до `endsAt + 1 год`. Раніше `endsAt` рахувався як час у UTC
(Railway TZ=UTC) і оголошення жили на 2–3 год довше; міграція `20261012120000_viber_listing_ends_at_kyiv_time`
перераховує наявні рядки.

## Нагадування про поїздки

`backend/src/booking-reminders.ts`, таймер раз на хвилину (`BOOKING_REMINDERS_INTERVAL_MIN`, `0` — вимкнено).
Час поїздки — київський. Для кожного бронювання:

| Нагадування | Коли | Умова |
|-------------|------|-------|
| `evening` («завтра») | 20:00 напередодні | бронь створена до 20:00 |
| `morning` («сьогодні») | 08:00 у день поїздки | бронь створена до 08:00 і до відправлення ≥ 30 хв |
| «перед поїздкою» | за **2 год** до відправлення; якщо на момент броні лишалося менше 2 год — за **30 хв** | лише коли бронь не потрапила ні під evening, ні під morning (напр. заброньовано о 11:00 на 17:00 → нагадування о 15:00); якщо до відправлення менше 30 хв — не нагадуємо |

Кожне нагадування — не більше одного разу (`BookingReminder`, унікально `bookingId + kind`): таймер, ручні
`POST /telegram/send-reminders[-today]` і два контейнери під час деплою не дублюють повідомлення. Прострочене
(сервер лежав довше 90 хв для evening/morning або 15 хв для «перед поїздкою») не надсилається. Канали ті самі:
бот → платний SMS-фолбек (одна SMS на бронювання, як і раніше).
