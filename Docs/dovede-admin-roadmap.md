# Адмінка «Доведе»: план планів (файл відновлення)

Запит власника (2026-11-18): вкладка `/admin/dovede` — «одна велика простиня наліпленого». Потрібно: зручна структура,
налаштування в адмінці без розробника, навчання міст (обхід у ширину) на сервері, а не на ноутбуці. Перевірка задуму:
«завтра кажу „навчи Житомир“ — і роблю це сам в адмінці, результат базово пристойний».

План зібрано з трьох досліджень (2026-11-18): опис усього, що вміє вкладка й де живе кожне налаштування; дизайн
навчання на сервері; структура вкладки й спільні деталі адмінки. Тут — підсумок і порядок робіт; подробиці кожного
треку — у його розділі нижче. Кожен пункт — один PR, із тестами, без «великого вибуху».

## Що зараз (коротко)

- Вкладка — один стовпчик: плитки журналу → «Чого не впізнали» (30 рядків) → «Синоніми» (усі, без ліміту) → «Звідки
  забирають попутки» (згорнуто) → «Місто: що вже знаємо» (згорнуто; всередині — налаштування, 4 кнопки, «Місця») →
  «Питання» (до 300 рядків). Усе одним стилем кнопок-«чіпів»: фільтр, збереження й «заархівувати все з Google»
  виглядають однаково. На телефоні таблиці їдуть убік (у CSS немає жодного `@media`).
- Налаштування розкидані: строк свіжості й ліміт Google — в адмінці (ліміт — PR #196); ліміт Claude
  (`DOVEDE_DAILY_CAP`), вмикачі (`DOVEDE_PUBLIC`, `DOVEDE_ENABLED`, `DOVEDE_CITY_ROUTES/REFRESH/OWN`), ліміт часу авто
  (`DRIVE_TIME_DAILY_CAP`) — лише змінні на Railway; частка навчання (половина ліміту), розмір кроку, тиждень паузи
  після «маршруту немає» — константи в коді.
- Знайдено попутно:
  - сервер тримає **два окремі** обʼєкти дороги містом (один для людей у роутері, другий для фонового навчання в
    `index.ts`): пауза після відмови Google (429/403), остання помилка й лічильник «у памʼяті» між ними не спільні;
  - `stats().unanswered` (до 100 пар без відповіді) сервер уже віддає, а адмінка його не показує;
  - скільки викликів Google за день зробив «час авто» (`drive-time.ts`) — не видно ніде;
  - синонім видаляється назавжди (на відміну від правила «лише архів» для таблиць міста).

## Треки

### A. Каркас вкладки й спільні деталі адмінки (frontend)

Розділи з власними адресами `/admin/dovede/<розділ>` (маршрут `/admin/:tab/:section?`):

| Розділ | Що там | Головна дія |
|---|---|---|
| Огляд (без сегмента) | рядок стану (ШІ N/ліміт · Google N/ліміт · Навчання), плитки «сьогодні», «Потребує уваги»: невпізнані слова, розбіжності, пари без відповіді, підозрілі дороги, останній прогін навчання | перейти до виправлення |
| `questions` Питання людей | період і фільтр поруч зі списком, плитки розуміння, «Чого не впізнали», список питань | «Навчити слово» в рядку, «Відкрити як людина» |
| `dictionary` Словник | форма синоніма (з `?word=`), пошук, «N з 300», черга невпізнаних, примітки водіїв (згорнуто) | «Навчити» |
| `city` Місто: база доріг | Київ / Житомир (`?misto=`), лічильники, «Місця» з пошуком і сторінками, «Що питають» (і всі без відповіді) | «В архів» |
| `learning` Навчання | трек B: пресети, оцінка, хід, підозрілі; фонове навчання й «Крок зараз» | «Почати» |
| `settings` Налаштування | рядки налаштувань групами ШІ / Google / Фонове навчання / «Задано на сервері» (лише читання) | «Зберегти» / «Скинути до типового» |

Небезпечні дії («заархівувати все з Google», «скинути лічильник попиту») — у згорнутій «Небезпечній зоні» розділу
«Місто». Довідка — під «?», не абзацами. Телефон: розділи — гортальний ряд, таблиці під 640 px стають картками (лише
CSS, розмітка лишається таблицею — тести не ламаються), кнопки на всю ширину.

Спільний набір `AdminPage/kit/` (для всіх вкладок адмінки, на змінних `--pb-*`): `AdminSectionNav`,
`AdminSectionHeader`, `AdminCard` (згортається, `lazy`, `tone="danger"`), `StatusPill`, `StatTile(s)`, `ChipGroup`
(лише фільтри й періоди), кнопки main / secondary / danger, `SettingRow` (значення, типове, джерело, перевірка,
«Скинути до типового»), `EmptyState`, `ResponsiveTable`.

### B. Навчання на сервері (backend + розділ «Навчання»)

- **Кампанія** (`DovedeCityCampaign` + вузли обходу `…Place` + питання-журнал `…Ask`; нічого не видаляється, лише
  `archivedAt`): місто, пресет, план (точки, напрямки, години), глибина, бюджет усього / на день, запас для людей,
  стан (`queued · running · waiting · paused · blocked · done · cancelled`), лічильники, звіт.
- **Виконавець** — ще одна фонова задача в `index.ts` (раз на хвилину, до 20 питань за крок). Кампанію бере умовне
  оновлення рядка з терміном на 2 хв — двоє контейнерів під час деплою не заважають одне одному; кожне питання
  береться окремо, повтор безпечний (запис у базу — upsert). SIGTERM відпускає кампанію одразу.
- **Спільний ліміт Google**: денний лічильник і пауза після відмови — у базі (`DovedeCityGoogleDay`: люди / фонове /
  кампанія / скільки людям відмовили), одна копія «дороги містом» на весь сервер. Кампанія питає, лише поки лишається
  запас для людей (типово ≥ 50 або 20 % ліміту), рівномірно протягом доби, і стає до завтра, якщо хоч одній людині
  сьогодні відмовили через ліміт. 429 — чекати 30 хв; 403 — зупинитись і написати власнику з текстом Google.
- **Спільний код**: ядро обходу (`candidates`, фільтр сміттєвих назв, години, …) переїжджає в
  `backend/src/dovede/crawl-core.ts`; форма назви «як у сторінки» (`farDetails`, `nominative`) — окремий модуль
  `nlu/cityDetail.ts` з побайтовою копією на бекенді й тестом рівності з `parseLocal`. Списки місць — у
  `backend/src/dovede/learn-places.ts`. Локальний `npm run dovede:crawl` лишається інструментом розробника.
- **Пресети** (оцінку показуємо до старту: скільки питань, скільки вже знаємо, скільки піде в Google, за скільки днів):
  - «Навчити Житомир» — список місць Житомира, кінцеві всіх маршрутів, питання людей без відповіді; від автовокзалу
    туди й назад; спершу будні 09 / 17, потім для знайдених — 07 / 12 / 14 / 20 і субота / неділя 11 / 17; глибина 2,
    бюджет ~800, ~250 на день;
  - «Навчити Київ» — те саме для Києва (від Академмістечка й вокзалу), бюджет ~1500;
  - «Дообучити: вечір / вихідні / ранок» — уже відомі місця, лише названі години, без розширення;
  - «Питання без відповіді», «Види транспорту» (`MODE_PAIRS` на всі години), «Освіжити застаріле», «Свій список».
  - Пізніше — фраза замість кнопки («дообуч Київ на вечір і вихідні» → той самий план, показаний до старту).
- **Звіт якості** після прогону: частка «маршруту немає»; підозрілі — однаково короткий час від далеких точок (як
  «Торговельно-економічний університет»), «одразу поруч» з точкою, кілька різних назв в одну зупинку, сильна
  різниця туди / назад; відкинуті як сміття назви. Біля кожного підозрілого — «Відкрити як людина», «В архів»,
  «Нормально».
- **Вартість**: кожен виклик Google коштує, і «маршруту немає» теж. За прайсом Routes — орієнтовно $5–10 за 1000
  (безкоштовна частина щомісяця); Житомир ~800 викликів ≈ до $8, Київ ~1500 ≈ до $15. Точну категорію TRANSIT
  перевірити у звіті білінгу Google Cloud до першого великого прогону.

### C. Те, що власник має міняти сам (налаштування й дані)

Реєстр налаштувань на бекенді (`backend/src/dovede/settings.ts`: ключ, підпис, межі, типове зі змінної, довідка;
значення в базі, `null` — типове) і екран «Налаштування». За цінністю:

1. Ліміти: Claude на день, Google на день (вже PR #196), час авто на день — з видимим «сьогодні N».
2. Вмикачі: ШІ-розбір, пошук містом, фонове оновлення, власні дані Житомира; запуск для всіх (`DOVEDE_PUBLIC`) — з
   підтвердженням. Змінна на Railway лишається головним вимикачем; ключі й паролі — лише на сервері, не показуються.
3. Фонове навчання: частка ліміту (зараз 50 %), пар за крок, інтервал, за скільки днів оновлювати, пауза після
   «маршруту немає», стартові пари (без `MODE_PAIRS`, які звіряє тест).
4. Дані, що змінюються в житті й зараз потребують коду та деплою: автобус замість метро (`METRO_SHUTTLE`), тариф і
   години метро, дати додаткових рейсів кільцевої, приклади питань на сторінці, телефони «Зубастика».
5. Вартість ШІ в гривнях за період і строк зберігання текстів питань (рішення «до публічного запуску» з роадмапу).

### Крок 6 — як зроблено (і чим відрізняється від задуму вище)

- Код: `backend/src/dovede/city-campaign.ts` (заготовки, план, оцінка, виконавець, керування), таблиці
  `DovedeCityCampaign` / `…Place` / `…Ask` (міграція `20261120100000_dovede_city_campaigns`), фонова задача
  `dovede-city-campaign` (`DOVEDE_CITY_CAMPAIGN_INTERVAL_MIN`, типово 1, `0` — вимкнено). У «дорозі містом» —
  `campaignAsk` (каже, чи пішов запит до Google: бюджет рахує саме їх), `peekMany` (що вже є, нічого не пише) і
  `googleBudget`.
- API (лише адмін): `GET /admin/dovede/city/campaigns/presets`, `POST …/campaigns/preview` (оцінка: рівень 0 — точно за
  базою, глибше — «від і до», пропонований бюджет і денна частка), `POST …/campaigns` (`budget`, `dailyBudget` —
  погоджені власником числа запитів), `GET …/campaigns`, `GET …/campaigns/:id`,
  `POST …/campaigns/:id/action { pause | resume | cancel | extend | archive }`.
- Заготовки: «Навчити місто» (Житомир — від автовокзалу туди й назад, глибина 2; Київ — від Академмістечка й
  Київ-Пасажирського, глибина 1; будні 09, для знайдених — ще 17), «Дообучити: вечір / вихідні / ранок» (уже відомі
  місця, лише ці години), «Питання людей без відповіді», «Види транспорту» (Київ), «Свій список». Інші години для
  знайденого — окремою кампанією «Дообучити…», щоб кожну витрату власник бачив і погоджував.
- Запас для людей — `reserveFor(ліміт)` = п'ята частина, не менше 50: кампанія питає Google, лише поки за день
  витрачено менше ніж ліміт мінус запас. Рівномірного розподілу протягом доби й правила «стати до завтра, якщо людині
  відмовили» немає: запасу досить, а кампанія за хвилину ставить не більше 20 питань.
- 429 — чекати 30 хв («quota»); 403 — теж чекати 30 хв («denied»), без зупинки; сповіщення в адмін-чат — крок 8
  разом зі звітом якості й «Освіжити застаріле». Три збої Google поспіль — пауза 15 хв.
- Веде одна кампанія за раз — найстаріша, яку зараз можна вести (та, що чекає на свою денну частку, пропускає чергу
  наступній). Стани в базі: `running · waiting · paused · done · cancelled` (`queued` і `blocked` не знадобились).
