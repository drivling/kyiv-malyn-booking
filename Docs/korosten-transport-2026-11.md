## Що просив власник (2026-11-09)

Увімкнути `korosten.kiev.ua/transport` (зараз заглушка «скоро»): у Коростеня є відкриті дані. Адмінка спільна з
Малином — організувати акуратно, ітераціями, з відновленням. Підписатись на джерела Коростеня: раптом
опублікують оновлення.

### Рішення власника

1. Мета — повний набір (зупинки, карта, табло, планувальник). Прапорець «Локальний транспорт» у вкладці
   «Маршрути» вмикає власник, коли вирішить — можливо посередині. Перед цим він питає «чи безпечно», відповідь —
   за таблицею «Готовність до ввімкнення» нижче.
2. Зупинки: назви з data.gov.ua, чернетка координат з OSM, решту власник бере з Google Maps. Автозбір з Google
   Maps робимо, де можливо, — через офіційні API Google Maps Platform з ключем власника. Вебсторінку
   maps.google.com не парсимо (захист від ботів не обходимо).
3. Лист до ради надсилаємо, але відповіді **не чекаємо**: коли наша сторона готова — запуск вирішує власник.

## Архітектура

Сьогодні транспорт повністю однотенантний: глобальні id зупинок / маршрутів / рейсів, `TransportMeta` — один
рядок `id=1`, `PUT /transport/dataset` стирає всі таблиці без фільтра, фронтенд і `dist/` містять лише малинські
дані, тексти, схему й кольори.

**Зберігання — колонка `cityCode` + складені ключі.** `TransportStop/Route/Trip`: `@@id([cityCode, id])`;
`RouteStop/Segment`: складені FK і unique з `cityCode`; `TransportMeta`: `cityCode @unique @default("Malyn")`
(рядок `id=1` лишається малинським); `TransportRevision`: `@@id([cityCode, revision])`; `StickerScan/Return/Print`
і `TransportArrivalReport`: проста колонка `cityCode`. Малин = default, його id, URL і відповіді не змінюються.
Відкинуто: префікси id у сховищі (вічний податок на мапінг у кожному сирому запиті) і «потворні» публічні id (`k2`).

- Id маршрутів `[a-z0-9]`: «2-Б» → id `2b`, `shortName` «2-Б». Зупинки Коростеня: `z-0NN` → `st_10NN` (діапазон не
  перетинається з малинськими — витік між містами одразу видно; `STOP_ID_RE` не чіпаємо).
- Захист від втрачених оновлень, журнал ревізій, кеші GTFS/RSS — по місту.

**API — необов'язковий `?city=<TripPoint.code>`** на наявних шляхах; без параметра = Малин, байт-у-байт. Один
хелпер `resolveTransportCity(req)` (`backend/src/transport-city.ts`). **Серверний гейт:** для міста з
`hasLocalTransport=false` публічні GET → 404, крім запиту з адмін-токеном (`no-store`) — чернетка не витікає.
GTFS/RSS/ICS Коростеня → 404 до фази відкритих даних. `serve-dist.mjs` на вторинному хості дописує `city=` у 302.

**Фронтенд** — профіль транспорту міста (`frontend/src/site/transportProfiles.ts`: форми назви, центр,
тексти/SEO, `hasScheme`, `hasStopArticles`, `openData`); методи `api/client.ts` і `useTransportDataset` отримують
місто (ключ localStorage Малина той самий, для інших — `transport-dataset:v1:<city>`); `routeNo` і кольори — по
місту (кольори Коростеня в `meta.routeColors` — **зі схеми власника 2019 року**, див. «Схема Коростеня»); статті
зупинок лише для Малина; сторінка схеми Коростеня — окрема фаза 12, до неї `/transport/scheme` там сховано. На вторинному хості `serve-dist` перестає віддавати малинські `dist/transport/**`,
редиректи зупинок і список 410 → SPA. Пререндер / індексація / PWA Коростеня — пізні фази.

**Спільна адмінка** — перемикач `?city=Korosten` (той самий ключ, що в API; рідне місто між доменами їде в `?homeCity=`) на
чотирьох транспортних вкладках і `/admin/wall`, хук `useAdminTransportCity()`, яскравий банер «Редагуєте:
КОРОСТЕНЬ». Перегляд публічних сторінок до запуску: `malin.kiev.ua/transport?city=Korosten` — працює лише з
адмін-токеном, липкий у `sessionStorage`, банер «Перегляд: Коростень, не опубліковано».

**Підписка на джерела** (фаза 1, зроблено) — `WatchedSource` + `backend/src/transport-source-watch.ts`, розділ
«Стеження за джерелами» в `RAILWAY_CRON_REMINDERS.md`.

**Автозбір з Google Maps** (фаза 8; перший крок — перевірити, чи API взагалі знає транспорт Коростеня):

- `data/korosten-transport/scripts/gmaps-draft.mjs`, ключ `GOOGLE_MAPS_API_KEY` (власник створює в Google Cloud;
  у хмарній сесії — через форму секретів, у чат не вставляти; хости `routes.googleapis.com`,
  `places.googleapis.com` — в allowlist середовища).
- Routes API, режим TRANSIT між кінцевими кожного маршруту (обидва напрямки, кілька годин дня): з кроків
  транзиту — лінія, назви й координати зупинок посадки/висадки та проміжні. Якщо API віддає лише
  посадку/висадку — запити парами сусідніх зупинок зі `stops.csv`.
- Places API (Text Search) за `<назва>, <вулиця>, Коростень` для зупинок, яких не виявилось у маршрутах.
- Результат — кандидати в робочий аркуш (джерело `gmaps`, відстань до чернетки OSM, розбіжності назв); сирі
  відповіді — в `data/korosten-transport/gmaps/`. Спірні підтверджує власник.
- Застереження (рішення за власником): умови Google Maps Platform обмежують довге зберігання координат з API й
  побудову на них власної бази — тому фінальні координати позначаємо як перевірені власником; понад безкоштовний
  ліміт запити платні (обсяг тут — сотні запитів).

**Помічник Google Maps** (те, що автозбір не закрив):

- Робочий аркуш `data/korosten-transport/worksheet/stops.html` (+ CSV): 91 зупинка — назва, вулиця, чернетка
  координат, готові посилання «відкрити в Google Maps», колонка «вставити координати».
- Для кожного маршруту — посилання Google Maps «маршрут транспортом» між кінцевими й поле для порядку зупинок.
- Парсер вставки (чистий, з тестами): `50.9506, 28.6384`, посилання з `@lat,lng`, `!3d…!4d…`, `/dir/…/lat,lng`.
- У редакторі карти (місто Коростень): поле «вставити координати / посилання Google Maps» біля зупинки, список
  зупинок без координат, посилання «відкрити в Google Maps».
- Імпорт заповненого аркуша скриптом `--apply` (бекап → PUT з `city` і `baseRevision` → звірка).

## Схема Коростеня

Власник намалював схему маршрутів Коростеня приблизно 2019 року, коли жив там:
[`data/korosten-transport/scheme-2019/`](../data/korosten-transport/scheme-2019/README.md) (JPEG, таблиця
кольорів, що застаріло). Рішення власника (2026-11-09):

- **Кольори ліній — з цієї схеми.** Вони йдуть у `meta.routeColors` Коростеня вже у фазі 8 і далі всюди, де в
  Малина колір зі схеми: чипи маршрутів, лінії на карті, табло, наклейки. Номер на кольорі — не завжди білий, як
  на схемі 2019, а за правилом сайту `textColorOn()` (на світлих №3, 6, 6А, 7, 8, 12, 14 виходить чорний).
- **Архітектура (геометрія) — теж з неї:** сітка 45°, пучок ліній через центр, вокзал і ринок як вузол, петлі
  Київської / Гастелло / Цегельного заводу, річка й залізниця як орієнтири.
- **Мета — зробити краще, щонайменше інтерактивною:** натиск на лінію підсвічує її й веде на сторінку маршруту,
  натиск на зупинку — на табло; пошук зупинки; підсвітка «мій маршрут» з планувальника. У Малина частина цього
  вже є (`LocalTransportSchemePage`, `schemeMini`, `data-route`) — беремо той самий механізм, а не пишемо другий.
- **Порядок зупинок на лініях схеми — чернетка ланцюжків** для фаз 8–9 (у даних ради його нема взагалі).
  Друге джерело порядку зупинок — сайт, адресу якого власник дасть пізніше: записати його в
  `data/korosten-transport/SOURCES.md` (що там є, ліцензія) і звіряти ланцюжки за обома; де розходяться —
  вирішує власник.

Що виправити проти версії 2019 (до під-плану фази 12):

1. Близькі кольори в одному пучку: три фіолетові (2, 2Б, 3), чотири зелені (6, 6А, 6Б, 12), 7 і 7А майже
   однакові. Розвести за світлотою або дати варіантам штрих / подвійну лінію замість нового відтінку.
2. Вузол вокзал – ринок: не видно, яка лінія де зупиняється і куди повертає. Розкласти на окремі зупинки з
   позначками на кожній лінії.
3. Односторонні петлі без стрілок напрямку.
4. Номер лінії стоїть лише в одному місці й далеко від кінцевої — повторити біля кожної кінцевої і в пучку.
5. Нема позначок пересадок.
6. Актуалізувати склад: перейменування («Гастелло» → «Романа Шухевича»), маршрути, яких у розкладі ради 2026
   вже нема (6А, 6Б, 7А, 12, 14) — прибрати або показати як варіанти.

Якщо знайдеться вихідний вектор схеми — покласти в ту саму теку: кольори й геометрія тоді беруться точно.

| PWA | воркер і маніфест на вторинному домені — 404 | 13+ |

Дивитись, що побачать люди, можна **до** ввімкнення: адмінка → транспортна вкладка → місто «Коростень» →
«Переглянути сторінки міста» (див. «Фаза 6» у знахідках).

**Вмикати безпечно** не раніше, ніж закрито фази 3–6 і 10 і в датасеті Коростеня є зупинки з координатами й
ланцюжки хоча б для частини маршрутів. До того прапорець покаже малинський транспорт на домені Коростеня.

## Пастки

- `backend/dist` перезбирати й комітити з кожною зміною `src`; husky pre-commit ганяє `npm test`.
- `tripTiming.ts` ↔ `backend/src/trip-timing.ts` байт-ідентичні; `site-hosts.mjs` ↔ `site-domains.ts` синхронні
  (третю карту міст не заводити).
- Списки API-шляхів: `apiRedirectPath` ↔ `isTransportApiPath` (воркер) ↔ проксі `vite.config.ts`;
  `openapi.test.ts` звіряє yaml і маршрути в обидва боки.
- `fillOmittedRouteFields`, редиректи зупинок, `recalculate-segments` мусять мати scope міста, інакше дані Малина
  протечуть в однойменний маршрут.
- Кожен новий шлях запису викликає `snapshotTransportDataset` + `recordTransportRevision` з містом; скрипти
  Коростеня завжди шлють `city` і `baseRevision`.
- Збірка фронтенда тягне живий API; локальний `npm run build` переписує знімок коридорів — дивитись `git diff`.
- `?site=` сам доступу до даних не дає — лише адмін-токен.
- До сайту ради й data.gov.ua — один запит на джерело за тік; жодного обходу захистів.
- `?city=` в адресі сторінки — місто транспорту (адмінка, перегляд); рідне місто між доменами — лише `?homeCity=`.
  Старих посилань із `?city=` для рідного міста не підтримуємо (рішення власника 2026-11-11), інакше передача рідного
  міста знову з'їдала б параметр транспорту.

## Знахідки по фазах

### Фаза 0 (2026-11-09)

- Сторінка ради — не «відкриті дані»: ліцензії нема. Відкриті дані ради лежать окремо на data.gov.ua (CC BY) і
  не містять ні координат, ні часу — два джерела доповнюють одне одне.
- `timezone` у наборах ради — `Europe/Korosten` (такої зони нема); при імпорті — `Europe/Kyiv`.
- Overpass (`overpass-api.de`) з хмарної сесії недоступний — OSM-чернетку запускати локально або додати хост в
  allowlist середовища.
- `?site=korosten` діє і на проді (перевірки хоста нема), але не липкий між переходами.

### Схема власника (2026-11-09)

- Схема 2019 року покриває одразу дві прогалини даних ради: кольори ліній і порядок зупинок.
- На ній 14 ліній, у розкладі ради 2026 — 9: звірка складу — перший пункт під-плану фази 12 і частина фази 8.
