# «Джура» · фаза 0 — ручний smoke-чекліст

Python поза CI, Telegram живий — тож після деплою проходимо руками. Потрібен другий акаунт
(колега або тестовий) у тестовій групі. Roadmap: `dzhura-roadmap.md`.

## 0. Деплой і старт

- [ ] Міграція `20260925120000_dzhura_phase0` застосувалась (`prisma migrate deploy` у логах старту).
- [ ] У логах Railway після `[lunch] listening group=…`: `[dzhura] attached me=… lunch_group=…`,
      потім `[dzhura] watching 1 chat(s): Обіди…` і `[dzhura] dialogs synced: {'dialogs': N, 'chats': M}`.
- [ ] `/admin/dzhura`: статус «Слухач активний · N с тому»; у таблиці є група обідів із заблокованою
      галочкою «Читати» і бейджем «група обідів»; «В Обране» знята.
- [ ] Список груп заповнений (канали й боти відсутні, особисті чати не показуються).

## 1. Читання без «прочитано»

- [ ] Увімкнути «Читати» для тестової групи. Протягом ≤ 5 с у логах нічого не падає.
- [ ] З другого акаунта написати в групу текст. У БД з'явився рядок `DzhuraMessage`
      (`source='live'`, `senderPersonId` → `DzhuraPerson` з ім'ям/ніком; телефон — лише якщо контакт).
- [ ] **Головне:** у другого акаунта повідомлення лишилось з однією галочкою (не прочитане), поки
      власник сам не відкрив чат. Статус власника не став «онлайн».
- [ ] `lastMessageAt`, «Збережено» в таблиці адмінки оновились після «Оновити».

## 2. Дубль у «Обране»

- [ ] Увімкнути «В Обране». Написати з другого акаунта ще раз → у Saved Messages власника прийшов
      `<b>Назва</b> · Ім'я (@нік) · #id` + текст; ім'я клікабельне (веде в профіль).
- [ ] Відповісти з другого акаунта reply-ем → у дублі є рядок `↩︎ у відповідь на: «…»`.
- [ ] Надіслати фото з підписом → дубль `[фото] підпис`; файл → `[файл: назва]`. Самі медіа не
      переслані.
- [ ] Написати в групу **з акаунта власника** → у БД є (`isOutgoing=true`), в Обраному дубля немає.
- [ ] Група обідів: замовлення в ній збережені в `DzhuraMessage`, в Обране не дублюються, лунч-бот
      відповідає як раніше.

## 3. Реакції

- [ ] Другий акаунт ставить ❤️ на повідомлення власника → `DzhuraReaction` (автор, `isMine=false`),
      `reactionsJson = {"❤️": 1}`, в Обраному: `Ім'я: реакція ❤️ на ваше повідомлення «…»`.
- [ ] Знімає реакцію → у рядка з'явився `removedAt`, `reactionsJson` порожній, дубля про зняття немає.
- [ ] Власник ставить реакцію → рядок з `isMine=true`, дубля немає.
- [ ] Реакція на старе повідомлення (до ввімкнення галочки) → повідомлення підтягнулось у БД без дубля,
      реакція записана й продублювана.

## 4. Правки й видалення

- [ ] Другий акаунт редагує текст → `text` новий, `editedAt` заповнений, `editHistoryJson` містить
      попередню версію.
- [ ] Видаляє повідомлення у супергрупі → `deletedAt`; у basic-групі — теж, якщо id однозначний.

## 5. Список чатів, довантаження, експорт

- [ ] «Оновити список чатів» → кнопка «Оновлюємо список…», за кілька секунд «Список чатів оновлено»,
      нова група (створити тестову) з'явилась.
- [ ] «Історія…» → дати за останні 3 дні → «Довантажити з Telegram» → прогрес «переглянуто … збережено …»
      → «Готово: нових N…»; лічильник «Збережено» зріс; в Обраному дублів немає.
- [ ] «Вигрузити JSON» → файл `dzhura-<slug|chat-id>-<from>_<to>.json` відкривається: `project: dzhura`,
      `range.timezone: Europe/Kyiv`, id як рядки, у повідомлень є `sender`, `reactions`, `editHistory`.
- [ ] Дата «до» раніша за «від» → червоний алерт без запиту.
- [ ] Повторний backfill з тими ж датами, поки перший біжить → 409 «Така задача вже виконується».

## 6. Стійкість

- [ ] Зняти «Читати» → протягом ≤ 5 с нові повідомлення не пишуться; «В Обране» скинулась автоматично.
- [ ] Викликати ексклюзивну userbot-сесію (промо-DM з адмінки) → слухач зупинився й піднявся; повідомлення,
      написані під час паузи, підтягнулись gap-fill-ом (`[dzhura] gap-fill …`), без дублів в Обраному.
- [ ] `LUNCH_LISTENER_ENABLED=0` → адмінка показує «Слухач вимкнений на сервері». Зупинений процес →
      «Слухач не відповідає» протягом ≤ 60 с.
- [ ] `DZHURA_ENABLED=0` → у логах `[lunch] dzhura disabled`, лунч працює як раніше.
