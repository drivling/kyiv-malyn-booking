# «Як доїхати» (транспорт Малина) як PWA — ручна перевірка (smoke)

У CI e2e з реальним service worker нема: він потребує `npm run build` проти живого API і `serve-dist`
(Playwright у CI ходить через `vite dev`, де воркера немає). Тому після деплою (`Docs/transport-pwa-2026-10.md`) —
спочатку скрипт `npm run pwa:smoke` (розділ нижче), далі цей чекліст на malin.kiev.ua, а локально — на
`node scripts/serve-dist.mjs` поверх свіжого `dist/` (`http://localhost:4173` — localhost теж secure context).

## Скрипт `npm run pwa:smoke` (frontend, лише вручну)

`frontend/scripts/pwa-smoke.mjs` — Playwright-скрипт з реальним воркером проти задеплоєного сайту; не в CI і не в
pre-commit. Headless Chromium (430×900, uk-UA, Europe/Kyiv) відкриває базовий URL (за замовчуванням
`https://malin.kiev.ua`; інший — аргументом: `npm run pwa:smoke -- http://localhost:4173`), сам качає
`<base>/transport/dataset.json` і бере з нього перший не-`unreliable` маршрут та його першу зупинку. Покриває перші
п'ять пунктів чекліста Chrome нижче: **онлайн** — воркер `activated` зі scope `/transport`, `BUILD_ID` відповідає, один
кеш `malin-transport-shell-<id>` з оболонкою, усіма `/assets/*`, на які вона посилається, маніфестом, іконками і знімком,
копія в localStorage, після перезавантаження сторінка під контролем; **офлайн** (`context.setOffline` + abort усіх
запитів, і воркера теж) — `/transport`, табло, маршрут і схема відкриваються з воркера без жодного підресурсу з мережі,
з даними і смужкою стану, а `/mizhgorodski` падає як у звичайній вкладці; **«бекенд упав»** (abort лише
`GET …/transport/dataset`) — табло з копії зі смужкою «Сервер не відповідає…» і кнопкою «Оновити», а без копії — зі
знімка збірки; **знову онлайн** — смужка зникає, копія пишеться знову. Підсумок — таблиця PASS/WARN/FAIL, код виходу 1
при будь-якому FAIL (WARN — лише порада: кеш шрифтів, `cache-control` воркера після CDN). `PWA_SMOKE_SHOTS=<dir>`
додатково пише скріншот кожної перевіреної сторінки.

Застереження: під емуляцією Playwright `navigator.onLine` лишається `true`, тому навіть повністю офлайн сайт показує
гілку «Сервер не відповідає…». Скрипт лише підміняє `navigator.onLine` (init script) і перевіряє, що текст смужки
стає «Без мережі…»; справжнє визначення «мережі немає» — **тільки на телефоні** з вимкненим Wi-Fi і мобільними даними.
Встановлення, оновлення версії, вторинний домен, iOS і Lighthouse лишаються ручними пунктами нижче.

## Без домену (етап 5, `Docs/transport-verifiable-build-2026-10.md`)

Сценарій П1 маніфесту: домен не відповідає зовсім (DNS мовчить, хостинг зник, нас немає), а застосунок уже
встановлений або табло хоч раз відкривали. Воркер відповідає на навігацію `/transport*` оболонкою з precache ще до
того, як браузер піде в мережу, тож DNS йому не потрібен; дані — з локальної копії (`transport-dataset:v1`), а без неї —
зі знімка збірки у тому самому кеші. Перевірено 2026-10-20 локально (Playwright, headless Chromium 430×900) на підписаній
збірці (SRI): після першого онлайн-відкриття `serve-dist` **зупинено** — усі адреси нижче відкрились із воркера з
`transferSize 0`, без жодного підресурсу з мережі й без помилок у консолі, крім `ERR_CONNECTION_REFUSED` на API, тайли й
gtag.

Як відтворити:

- Локально: `npm run build` (потрібен API для пререндерів), `node scripts/serve-dist.mjs`, відкрити
  `http://localhost:4173/transport/stop/st_0001`, дочекатись Application → Service workers **activated**; **зупинити
  serve-dist** (Ctrl-C) — і далі відкривати адреси з чекліста. «Сервер зупинено» для застосунку те саме, що «домену нема»:
  і там, і там з'єднання не встановлюється.
- На проді, десктоп: у `/etc/hosts` рядок `127.0.0.1 malin.kiev.ua` (DNS «забув» домен), перезапустити Chrome; відкрити
  встановлений застосунок «Як доїхати» або вкладку `https://malin.kiev.ua/transport`. Прибрати рядок після перевірки.
  На телефоні цей сценарій не відтворюється без DNS-фільтра — режим «В літаку» перевіряє «без мережі», а не «без домену».

- [ ] Домен не відповідає: `/transport`, `/transport/stop/st_0001`, `/transport/route/2`, `/transport/scheme` відкриваються,
  табло з відправленнями. Бекенд живе на іншому домені (Railway), тож поки він відповідає — дані живі й смужки нема; якщо
  зник і він — зверху **«Сервер не відповідає — показуємо збережений розклад станом на …»** з кнопкою «Оновити» (саме
  ця, не «Без мережі…»: `navigator.onLine` лишається `true`, бо мережа є — немає лише нас). Локально обидва варіанти:
  збірка з `VITE_API_URL=<прод API>` — перший, без нього (API на `localhost:3000`, якого нема) — другий.
- [ ] Сторінка транспорту, яку раніше не відкривали (інший маршрут, інша зупинка, навіть `/transport/stop/немає-такої`),
  теж відкривається: оболонка одна на всі `/transport*`, дані повні в копії/знімку.
- [ ] Перехід між сторінками всередині `/transport*` (клік по маршруту з табло) працює як SPA, без мережі.
- [ ] `/`, `/mizhgorodski`, `/about`, `/admin` — звичайна помилка браузера («не вдалося знайти сервер»): вони поза scope
  воркера і не precache-яться. Очікувано: без домену живе лише застосунок «Як доїхати».
- [ ] DevTools → Application → Service workers → **Update**: нічого не змінюється, воркер лишається `activated`
  (`reg.update()` відхиляється `TypeError`, `freshBuild` це ковтає); банера «нова версія» нема.
- [ ] `/about#build` (поки домен ще відповідає): збірка, `BUILD_ID` воркера і ревізія даних — ті самі, що
  `curl -s https://malin.kiev.ua/transport-sw.js | grep BUILD_ID`, `integrity` у джерелі сторінки і `/transport/revisions`.

Що **не** працює без домену — чесно:

- оновлення: нова збірка ніколи не прийде, застосунок лишається тим, що встановлено, до кінця свого життя в цьому
  браузері; якщо домен колись підніме хтось інший із власним `transport-sw.js`, браузер поставить **його** воркер
  (перевірка оновлення воркера — на кожній навігації після 24 год) — SRI й `BUILD_ID` дають це помітити, не заборонити;
- API: живий датасет, «Факт прибуття» й сканування наклейок (outbox тримає записи до 7 днів і 10 спроб, потім
  викидає), бронювання, довідка, міжміське табло, адмінка;
- карта (тайли OSM), Google Fonts поза вже кешованими, аналітика;
- перший візит і встановлення: без домену нема звідки взяти ні оболонку, ні знімок;
- життя копії: лише в тому браузері, де її створили; Chrome може витіснити кеш за браком місця, iOS Safari чистить
  сайт, не доданий на екран, після 7 днів без відвідин; інший браузер або пристрій — чистий аркуш.

## Вторинний домен і краулери

- [ ] `https://korosten.kiev.ua/transport.webmanifest` і `/transport-sw.js` → 404; Application → Service workers порожній.
- [ ] `curl -I https://malin.kiev.ua/transport-sw.js` → `content-type: text/javascript`; `cache-control: no-cache`,
  `cdn-cache-control: no-store`, `cf-cache-status: DYNAMIC` або `BYPASS`, жодного `max-age`. Cloudflare кешує `.js` за
  розширенням, і сам `no-cache` для нього означає «кешувати й перевіряти»: без `CDN-Cache-Control` (serve-dist,
  `NO_CACHE_HEADERS`) воркер лежав на edge до 4 год після деплою з переписаним `max-age=14400` (Browser Cache TTL зони)
  і `cf-cache-status: HIT` — встановлений застосунок тягнув попередню збірку (файл відновлення, «Фаза 6», знахідка 1).
  Якщо тут знову `HIT` / `EXPIRED` / `MISS` — заголовок перекрите Cache Rule з Edge TTL «Override origin» у панелі
  Cloudflare; тоді лікує правило «Bypass cache» для `/transport-sw.js`.
  `curl -I https://malin.kiev.ua/transport.webmanifest` → `application/manifest+json`, `no-cache`, `cf-cache-status: DYNAMIC`;
  `curl -I https://malin.kiev.ua/transport/dataset.json` → `application/json`, `no-cache`, `cf-cache-status: DYNAMIC`.
- [ ] `curl -s https://malin.kiev.ua/transport/stop/st_0001 | grep -c lt-status-bar` → `0` (смужка не запечена в HTML).
